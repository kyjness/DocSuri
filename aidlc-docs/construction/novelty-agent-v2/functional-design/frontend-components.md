# Novelty Agent v2 — Frontend Components

**Unit**: Novelty Agent v2 (U12) — FE 표면은 U13 Agent Chat의 novelty 모드
**Stage**: Functional Design (재설계 라운드, 2026-07-18)
**Scope**: 기능 정의 Q7=B(계약 재설계 허용)에 따른 FE 변경 범위. **채팅 화면·모드 구조(U13 `/agent`)는 유지**하고, novelty 모드의 결과 렌더링·진행 표시·대화 상호작용만 새 산출물 계약에 맞춘다. 구체 컴포넌트 구현·타입 생성은 Code 단계(공유 스키마 → `pnpm run gen:types`).

## 유지되는 것 (U13 계약)

- `/agent` 단일 route, 하단 네비 `에이전트` 탭, 새 채팅 시 모드 선택(문헌탐색&근거형성 / novelty), 세션 내 모드 고정(FR-40).
- 세션 drawer(목록·새 채팅·삭제), 멀티턴 메시지 구조(FR-41).
- 파일 첨부 drawer(PDF/Markdown/TXT)(FR-43).

## 바뀌는 것 (novelty 모드 내부)

### 1. 진행 표시 — 거시 상태 배지 + 활동 피드 (FR-35 개정, FD 게이트 Q2=B)

- **거시 상태 배지**: 접수 → 조사 중 → 보고 작성 중 → 완료/부분 완료/실패/취소. 구 11단계 타임라인 대체.
- **활동 피드**: 트레이스 파생 항목("'sparse retrieval' 계열 검색 중", "논문 4편 깊이 읽는 중")을 접을 수 있는 블록으로 메시지 사이에 표시 — U13 timeline 블록(FR-42)의 novelty 모드 구현체. 스트리밍 또는 폴링 갱신.
- 표시 항목: 활동 문구, 도구 종류, 질의 요약, 발견 수, 저하/거부 사유(사용자용). 내부 payload·민감 정보 비노출(SEC-9/15).

### 2. 조사 보고 렌더링 (FR-32 개정)

- **유사 연구 표**: v1 표 구조 승계(문제정의·방법·데이터셋·결과·한계·겹치는 점·근거 링크·근거 상태). 모바일(phone-first)에서는 행 단위 카드 접기.
- **여백 분석 섹션**: GapItem 카드 목록 — 영역, 판정(`이미 많이 연구됨`/`부분적`/`탐색 범위 내 미발견`), 판정 이유, 근거 링크(필수), `open_gap`은 탐색 범위 주석 병기. "새로움 보증"으로 읽히는 표현 금지(BR-NV10·BR-RA10).
- 근거 링크는 기존 논문 상세/리치뷰 이동과 연결. FR-47 확장 후에는 표·그림 앵커 링크가 해당 객체 위치로 이동.

### 3. 온디맨드 요청 UI (FR-32/33 개정, FR-44)

- 보고 하단·여백 카드에 **후속 요청 진입점**: "이 여백으로 방향 제안 받기", "실험 계획 만들기" — 누르면 채팅 입력에 요청 문구가 채워지는 방식(자연어 직접 입력도 동일 경로).
- 온디맨드 생성 중에는 해당 대화 턴에 로딩·활동 피드 표시. 생성물(방향 제안 카드, 실험 계획 카드)은 대화 턴 응답 + 보고에 산출물로 병합 표시.
- 실패·게이트 거부는 사용자용 사유와 재요청 버튼으로 표시.

### 4. 대화 스티어링 (FR-44)

- 실행 중에도 채팅 입력 활성 — 안내 문구로 "지시는 다음 판단 시점에 반영됨"을 표시.
- 스티어링 메시지와 온디맨드 요청은 같은 입력창을 쓰되 서버 분류 결과(kind)에 따라 응답 형태가 달라진다. FE는 분류하지 않는다.

### 5. 상태·제어

- **취소 버튼**: 실행 중 노출 — 협조적 취소 안내("진행 중 작업을 마치고 멈춥니다"), 취소 후 부분 결과 유지 표시.
- **부분 완료 banner**: 예산 소진·source 저하 시 보고 상단에 사유와 완성 범위 표시(FR-45, NFR-R3). 재시도는 "새 조사로 이어가기"(새 잡 생성) 경로.
- **Notion export**: preview → 승인 → export 흐름 유지(BR-NV17). v1 Agent Chat에서 export UI 제외였던 상태(FR-43)를 v2 FE 작업에서 도입할지는 Code 단계 백로그로 명시.

### 6. 제거되는 것

- 구 11단계 진행 타임라인(고정 enum 기반).
- 원고 위험 신호 패널(FR-34 폐기).

## API 계약 방향 (스키마는 Code 단계)

| 표면 | 방향 |
|---|---|
| 잡 API | 생성/조회/취소 유지. 조회 응답은 거시 상태 + 산출물 참조 + 저하 요약으로 재편. |
| 진행 피드 | 트레이스 파생 활동 피드 조회(폴링) 또는 스트리밍 — U13 timeline seam 재사용. |
| 대화 API | 잡 귀속 멀티턴 메시지 송수신(스티어링/온디맨드 공용) — 기존 novelty chat seam 재편. |
| 공유 스키마 | `shared/` 스키마 갱신 → 생성 타입 드리프트 가드(`gen:types` CI) 준수. |
