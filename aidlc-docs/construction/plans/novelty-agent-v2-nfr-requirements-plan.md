## 3. 명확화 질문

### Q1 — 루프는 어떤 프로세스에서 도나 (실행 표면)
루프 한 번이 수 분씩 걸리므로 API 요청 안에서 돌 수 없다. NFR-P5는 "API는 잡 관리만, 별도 워커가 실행"을 요구한다. 구 구현은 SQS 워커였는데 AWS가 은퇴했다.

- **A) 잡 큐 포트 + 별도 워커 프로세스 (1차 어댑터 = redis)** — 루프는 "잡 큐 포트" 뒤에서 돌고, 로컬 1차 어댑터는 이미 컨테이너에 있는 redis, 배포 재개 시 SQS 어댑터(기존 `real_wiring` 워커 계약)로 교체. NFR-P5 구조 유지, API 재시작이 실행 중 잡을 죽이지 않음. (권장)
- **B) FastAPI 백그라운드 태스크(in-process)** — 프로세스 하나로 단순 / API 재시작 시 실행 중 잡 유실, 협조적 취소·재접속 조회가 약해짐.
- **X) 기타**

[Answer]: A — 잡 큐 포트 + 별도 워커. 1차 어댑터 redis, 배포 재개 시 SQS 어댑터(기존 real_wiring 계약)로 교체.

### Q2 — LLM 프로바이더 (루프의 뇌)
루프는 도구 호출(function calling)을 지원하는 LLM이 필요하다. 로컬 이관 체제는 OpenAI 프로바이더 어댑터를 쓰고 있다.

- **A) 현 체제 유지 — OpenAI 어댑터 + 프로바이더 스위치 존중** — 기존 프로바이더 추상화 뒤에서 루프용 tool-calling 어댑터를 추가. 다른 프로바이더(Anthropic 등) 병행은 어댑터 추가로 열어둠(로컬 이관 §7 미룬 결정과 정합). (권장)
- **B) Anthropic API 병행 도입을 지금** — 어댑터 2종 동시 구축. *비교 실험 가능 / 이번 사이클 작업량 증가.*
- **X) 기타**

[Answer]: A — 현 프로바이더 스위치 유지, OpenAI tool-calling 어댑터 1차. 타 프로바이더는 어댑터 추가로 병행 가능.

### Q3 — MCP 서버 선정 (⑤ 2단계 대비 — 지금은 결정만, 구축은 ⑤)
FD는 위치(포트 뒤 어댑터)만 정했다. 어떤 서버를 쓸지 확정한다.

- **A) 검증된 기존 MCP 서버 셀프호스트** — arXiv·GitHub·Notion 모두 공식/커뮤니티 MCP 서버를 로컬 컨테이너로 셀프호스트하고 어댑터가 접속. 구현 비용 최소, 서버 코드는 신뢰 경계 밖으로 취급(allowlist가 어댑터에 있으므로 안전). (권장)
- **B) 자작 경량 MCP 서버** — 필요한 기능만 직접 구현. *통제 최대 / 작업량, ⑤ 2단계가 길어짐.*
- **C) MCP 없이 일반 API 어댑터로만** — arXiv/GitHub REST 직접 호출. *단순 / 로드맵 ⑤ 2단계(MCP 연동) 목표와 상충.*
- **X) 기타**

[Answer]: A — 검증된 기존 MCP 서버 셀프호스트(로컬 컨테이너). 구축은 ⑤ 2단계, allowlist는 우리 어댑터가 강제.

> **개정 (2026-07-25) — 답 철회, C에 가깝게 정정**: 본 문항은 상위에서 **MCP 도입이 확정됐다는
> 전제**로 서버 제품만 물었고(선택지 C의 기각 사유가 "로드맵 ⑤ 2단계(MCP 연동) **목표와 상충**"인
> 것이 그 전제를 드러낸다), 실제로는 도입 여부를 물은 문항이 어디에도 없었다. MCP는 ⑤ 고정
> 단계에서 해제됐으므로(`operations/solo-roadmap.md` 개정 블록) **A는 철회**하고, 현행은 C에
> 해당하는 **직접 구현 어댑터 유지**다(`adapters/external/` — TD-NV2-4 개정). 도입 자체를
> 금지하는 것은 아니며, 필요가 생기는 시점에 서버 선정과 함께 다시 결정한다.

### Q4 — 루프 예산 시작 수치 (FR-45)
정책(3중 한도)은 FD에서 동결. 시작 수치를 정한다 — 운영하며 조정 가능하되, 변경은 문서 갱신 동반.

- **A) 보수적 시작값** — 최대 반복 24회 / 도구 호출 총 40회(도구별: 검색류 12, form_evidence 4, view_figure 8, 저장 12) / per-job 비용 상한 $0.50(U6 배분 내). 소진 시 partial 종료. 개인 API 키 체제에 맞는 안전 시작점. (권장)
- **B) 여유 시작값** — 반복 50 / 호출 100 / $2.00. *깊은 조사 가능 / 폭주 시 비용 체감 큼.*
- **X) 기타** — 직접 수치 지정.

[Answer]: A — 보수적 시작값: 반복 24 / 도구 호출 총 40(검색류 12·form_evidence 4·view_figure 8·저장 12) / per-job $0.50. 조정은 문서 갱신 동반.

### Q5 — 진행 피드 전달 방식 (FR-35)
활동 피드를 FE에 어떻게 흘리나.

- **A) 폴링 우선** — 기존 잡 상태 폴링 seam에 활동 피드 커서 조회를 추가. FE 작업 최소, 로컬 체제 단순. 스트리밍(SSE)은 후속 개선 항목으로 명시. (권장)
- **B) SSE 스트리밍 도입** — 실시간성↑ / 로컬·FE 작업 증가.
- **X) 기타**

[Answer]: A — 폴링 우선(커서 기반 피드 조회). SSE 스트리밍은 후속 개선 항목.

### Q6 — 트레이스 저장소·보존 (FR-46)
`ToolCallRecord`를 어디에 어떻게 보존하나.

- **A) 기존 postgres에 잡 귀속 테이블** — 잡과 같은 트랜잭션 경계, owner-scoped 삭제 시 함께 삭제(BR-NV18 개정과 정합), 활동 피드 조회 인덱스 포함. 보존 기한은 잡과 동일(별도 TTL 없음). (권장)
- **B) 별도 로그 스토어(파일/외부)** — 잡 삭제와 분리되어 BR-NV18 위반 위험, 로컬 체제에 과함.
- **X) 기타**

[Answer]: A — postgres 잡 귀속 테이블, 잡 삭제 시 cascade, 보존 기한 = 잡 수명.
