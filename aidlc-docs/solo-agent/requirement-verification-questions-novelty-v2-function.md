# Novelty Agent v2 기능 정의 — 요구사항 명확화 질문

**단계**: INCEPTION → Requirements Analysis (솔로 유지보수 사이클)
**일자**: 2026-07-18
**상태**: ✅ 확정 (2026-07-18)
**결정 요약**: 임무 = 조사 + 여백 분석(제안·실험계획은 대화 요청 시 온디맨드)(Q1=X). 입력 = 주제 + 선택적 원고(Q2=A). 산출물 = 구조화 세트(Q3=X). 상호작용 = 채팅 모드 + 잡 + 대화 스티어링(Q4=B). 원고 위험 신호 폐기(Q5=B), Notion export 유지(Q6=A), 화면·API는 새 산출물에 맞춰 재설계 허용(Q7=B → 아키텍처 질문지 Q6 개정).
**목적**: novelty v2 에이전트가 **무엇을 하는 기능인지**(임무·입력·산출물·상호작용)를 기존 구현과 무관하게 백지에서 결정한다. "어떻게 만들 것인가"(루프·도구·안전장치)는 본 질문지 확정 후 유닛 질문 게이트(`solo-agent/plans/novelty-agent-v2-functional-design-plan.md`)가 담당한다.
**읽는 법**: 각 질문의 "(현행)" 표기는 지금 구현이 무엇인지 참고용으로 알려줄 뿐, 기본값이 아니다. 무엇을 골라도 된다.
**결정 방식**: `[Answer]:`에 선택지 문자 기입. 확정되면 → ① `requirements.md` 개정 블록에 반영 ② 아키텍처 질문지 Q6(API·화면 계약)을 결과에 맞게 재확인 ③ 유닛 질문 게이트 갱신 ④ 설계 문서 작성.

- **U6 비용 가드 단일 권위**: 비용 판단은 U6 `get_budget_state()`만 한다.

## Q1 — 핵심 임무

이 에이전트는 사용자에게 무엇을 해주는 존재인가?

- **A) 연구 아이디어 파트너** — 연구 주제(또는 원고)를 주면, 관련 연구를 조사하고 그 근거 위에서 차별화된 연구 방향과 실험 계획을 제안한다. *(현행 임무와 동일)*
- **B) 선행연구 조사원** — 관련 연구 조사·정리(연구 지도, 한계 분석)까지만 한다. 아이디어 제안은 범위 밖. *조사 품질에 집중 / 문헌탐색 기능과 역할이 가까워짐.*
- **C) 아이디어 생성기** — 조사는 최소한으로 하고 아이디어·실험 계획 생성에 집중한다. *가벼움 / 근거 얕은 제안 위험.*
- **X) 기타** — 직접 서술.

[Answer]: X — 기본 임무는 **조사 + 여백 분석**까지: 주제(또는 원고)를 받아 관련 연구를 조사하고, 무엇이 이미 있고 어디가 비어 있는지 판정해 보고한다. **방향 제안·실험 계획은 기본 산출물이 아니라 사용자가 대화로 요청할 때 만들어주는 후속 턴**(온디맨드)으로 둔다.

## Q2 — 입력

사용자는 무엇을 넣는가?

- **A) 자연어 주제·연구 의도 + 선택적 원고 업로드** *(현행)*
- **B) 자연어 주제만** — 원고 경로 폐기. *범위 축소.*
- **C) 인터뷰형** — 에이전트가 되물으며 연구 의도를 함께 구체화한 뒤 착수. *입력 품질↑ / 상호작용 설계 필요(Q4와 연동).*
- **X) 기타**

[Answer]: A — 자연어 주제·연구 의도 + 선택적 원고 업로드. 의도 해석은 에이전트 기본 능력이며, 착수 전 되묻기·구체화는 Q4=B의 대화 스티어링이 담당한다.

## Q3 — 산출물

작업이 끝났을 때 사용자 앞에 무엇이 남는가?

- **A) 구조화 세트** *(현행)* — 유사 연구 표 + 근거 링크 달린 차별화 후보 + 실험 계획 + (원고 입력 시) 위험 신호. *결과가 예측 가능·검증 게이트를 산출물별로 걸 수 있음.*
- **B) 축소 세트** — 차별화 후보 + 실험 계획만. 조사 결과는 과정 기록으로만 남김.
- **C) 자유 보고서** — 고정 구조 없이 에이전트가 근거 링크를 단 보고서(마크다운)를 작성. *유연·에이전트다움 / 구조 계약이 없어 검증은 인용 실재성만 가능, FE 결과 화면 재설계 필요.*
- **X) 기타**

[Answer]: X — Q1=X에 맞춘 구조화 세트. **기본**: 유사 연구 표 + 여백 분석(모든 항목에 근거 링크 필수). **온디맨드**(대화 요청 시): 방향 제안·실험 계획. 채팅에는 보고서형으로 렌더링하되 이면은 구조화 데이터로 유지 — 산출물별 결정론 검증 게이트를 걸기 위함(자율성은 출력 형식이 아니라 조사 과정에서 나온다).

## Q4 — 상호작용 방식

사용자와 에이전트는 어떻게 만나는가?

- **A) 잡 실행형** *(현행)* — 입력 → 실행 → 진행 표시 → 결과. 실행 중 개입 없음.
- **B) 잡 + 대화 스티어링** — 기본은 잡 실행형인데, 실행 중·완료 후 채팅으로 방향 수정과 후속 지시가 가능. *세션 메모리(잡 내 멀티턴)와 자연스럽게 연결.*
- **C) 완전 채팅형** — 문헌탐색처럼 채팅창에서 대화하며 진행. *진입 장벽 낮음 / 긴 작업(수 분)의 진행 표현이 채팅에 부자연, 문헌탐색과 UI 구분 모호.*
- **X) 기타**

[Answer]: B — 겉은 채팅 모드 그대로, 긴 조사만 잡으로 관리(진행 표시·부분 결과·취소·재열람)하고 실행 중·완료 후 대화로 방향 수정·후속 지시가 가능하다. 장시간 자율 작업을 채팅 표면에서 제공하는 표준 형태(deep research 계열)와 동형.

## Q5 — 원고 위험 신호 기능

표절 유사도·AI 어투 경고 *(현행: 원고 업로드 시 제공)* 를 어떻게 하나?

- **A) 유지** — 원고 경로의 산출물로 계속 제공.
- **B) 폐기** — v2 범위에서 제외. *에이전트 임무(Q1)와의 결합이 약하면 정리 대상.*
- **X) 기타**

[Answer]: B — v2 범위에서 폐기. 새 임무(조사+여백 분석)와 결합이 약한 별개 기능이므로, 필요해지면 독립 기능으로 재도입한다.

## Q6 — Notion export

Notion 내보내기 *(현행: 미리보기 → 사용자 승인 → export)* 를 어떻게 하나?

- **A) 유지** — 승인 후 export 방식 그대로.
- **B) 폐기** — v2 범위에서 제외.
- **X) 기타**

[Answer]: A — 미리보기 → 사용자 승인 → export 방식 유지. 조사 보고서는 내보내기 가치가 있는 산출물이며, 기존 승인 게이트 패턴을 재사용한다. *(2026-07-25 개정: 종전 "⑤ MCP 단계(Notion 연동)의 구체적 목표물" — MCP 고정 단계 해제로 Notion export는 현행 어댑터 경로를 유지한다.)*

## Q7 — 화면·API 계약 (아키텍처 질문지 Q6 재확인)

위 답들로 기능이 정해진 뒤, 화면과 API는?

- **A) 기존 재사용** — Q1~Q6 결과가 현행 기능과 사실상 같을 때 성립. 아키텍처 Q6=A(계약 유지) 그대로. *FE 작업 0.*
- **B) 기능에 맞춰 재설계 허용** — Q1~Q6에서 현행과 다른 답이 나온 만큼 화면·API도 새로 설계. 아키텍처 Q6을 B로 개정. *FE 작업 동반, 결정 트레이스 저장 원칙은 유지.*
- **X) 기타**

[Answer]: B — 기능이 달라진 만큼(여백 분석 신설, 실험 계획 온디맨드화, 위험 신호 폐기, 대화 스티어링 추가) 결과 렌더링과 잡 API 계약을 새 산출물에 맞춰 재설계한다. 채팅 화면·모드 구조는 유지. 아키텍처 질문지 Q6을 A→B로 개정하며, 결정 트레이스 저장 원칙은 그대로 유지한다.
