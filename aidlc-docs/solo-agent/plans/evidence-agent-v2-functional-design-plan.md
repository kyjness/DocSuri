**용어**: **루프** = "상황 보기 → 다음 행동 고르기 → 실행"의 반복. **도구** = 루프가 부르는 부품(스스로 판단하지 않음). **게이트** = 저장·통과 전 기계식 검사. **승격** = 코퍼스 밖 논문의 본문을 가져와 DocModel까지 만드는 것.

- **A) 6종 코어** — `corpus_search`(내부 하이브리드 검색, `mode="phrase"`로 정확 문구 검색 겸용) · `external_search`(코퍼스 밖 제목·초록) · `fetch_paper`(온디맨드 승격) · `read_paper`(DocModel 블록 읽기) · `view_figure`(2모드) · `extract_evidence`(근거 추출 + 게이트). 종료는 도구가 아니라 `decide`의 판단. 레지스트리는 novelty와 동일한 allowlist deny-by-default. (권장)

### Q2 — 근거가 쌓이는 시점 (루프와 게이트의 접점)

## B. 근거 계약

### Q5 — 초록 범위로만 인용되는 외부 논문의 출처 표기

코퍼스 밖이라 `IndexRecord`가 없다. 초록 범위 인용(요구사항 게이트 Q5=B의 폴백)을 어떻게 계약에 담는가.

**먼저 구분**: 승격되지 않은 논문은 두 종류이고 **한 종류만 이 문항의 대상**이다.
1. **에이전트가 고르지 않은 논문** — 초록을 보고 관련 없다고 판단한 것. **인용되지 않으므로 근거표에도 없고 저장 대상도 아니다.** 검색 결과는 그 턴의 트레이스에 요약(질의·건수)으로만 남는다.
2. **승격을 시도했으나 실패한 논문**(비OA·파싱 실패) — 초록으로만 인용된다. 이 문항의 대상.

- **A) `external:` 네임스페이스 + 버전 고정 식별자, 초록 원문은 보관하지 않는다** — `paperId="arxiv:2401.00001v2"`(**버전까지 박는다**), `recordRef="external:arxiv:2401.00001v2"`, `anchor` 없음, `sourceScope="abstract"`. 인용 시점 검증은 취득한 초록과 대조해 그 자리에서 끝내고, `quote`는 `SourceRef`에 남는다. 사후 감사가 필요하면 **그 버전을 다시 가져와** 대조한다 — arXiv은 개정 후에도 모든 버전을 영구 보존하므로 재취득이 곧 재현이다. 업로드 문서의 `userdoc:` 네임스페이스와 같은 계열. (권장 — 저장 0, 재현성 유지)
- **B) 인용된 초록 원문을 스냅샷 보관** — `external_abstract(paper_id, content_hash, text, fetched_at)` 공용 테이블에 중복 제거 저장. *감사 시 외부 의존이 없다 / **버전을 고정하면 재취득으로 같은 것을 얻으므로 실익이 없고**, 테이블·정리 잡·생명주기(공개 캐시 vs owner-scoped)라는 관리 대상만 는다. 용량 자체는 문제가 아니다 — 초록 1건 1.2~2.0 KB(로컬 픽스처 실측 5건: 1210·1426·1655·1686·1994자).*
- **C) 검색 결과 전부 보관** — *재현성은 최대지만 인용되지 않은 논문까지 쌓여 대부분이 노이즈다. 재검증에 필요한 것은 **인용된 출처**뿐이다.*
- **D) 근거표에서 빼고 "관련 논문" 목록으로만** — *계약이 단순해지지만 요구사항 게이트 Q5의 확정(배제하지 않는다)과 어긋난다.*
- **E) 초록만 코퍼스에 색인해 정식 `recordRef` 발급** — *표기가 균일해지지만 **본문 없는 레코드가 검색 결과에 섞여** 코퍼스가 오염되고, `sourceScope` 구분의 의미가 사라진다.*
- **X) 기타**

> **비-arXiv 외부 소스를 추가할 때 재검토**: A가 성립하는 근거는 arXiv의 버전 영구 보존이다. 버전 고정 재취득이 보장되지 않는 소스(일부 저널 메타데이터 등)를 외부 검색에 들이면 그 소스에 한해 B가 다시 필요해진다. v1 외부 검색은 arXiv로 한정한다.

[Answer]: **A**

### Q6 — 세션·트레이스 저장 스키마

(권장)
