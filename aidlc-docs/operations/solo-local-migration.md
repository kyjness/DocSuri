# Solo/Local Migration (2026-07) — 종료된 전환의 기록

> **Status**: ⛔ **폐기 (2026-08-16)** — 이 전환은 되돌려졌다. 실행 절차·환경변수 프로파일은
> 따라 하면 깨지므로 **삭제했다**. 아래는 무엇을 왜 했고 무엇을 배웠는지의 기록이다.
> 현행 설정은 [`.env.example`](../../.env.example), 배포 형상은 `ops/cdk/`를 보라.

## 무슨 일이었나

2026-07, 팀 AWS 예산이 종료되어 모든 관리형 리소스가 회수됐다. 서비스를 로컬 컨테이너
(postgres·redis·opensearch·s3proxy)로 옮기고, Bedrock이 사라진 자리에 개인 키로 쓰는 외부
프로바이더 어댑터를 끼웠다. 원칙은 **도메인 코드를 건드리지 않는 것**이었고, 실제로 전환은
어댑터 추가 + env 설정 + 재색인으로만 이뤄졌다 — 헥사고날 구조가 값을 한 지점이다.

2026-08, AWS가 복구되어 전환을 되돌렸다. Bedrock이 다시 현행이고 코퍼스는
`cohere.embed-v4:0`으로 재색인됐다. 외부 프로바이더 경로(임베딩 어댑터 2개 · LLM 어댑터 3개 ·
프로바이더 스위치 5개)는 저장소에서 제거됐다.

## 남은 교훈

**1. 같은 차원의 다른 임베딩 공간이 이 시스템의 가장 날카로운 모서리다.**
전환 당시 "차원 파라미터로 `vector_spec.DIMENSIONS=1024` 계약을 그대로 유지"한 것을 장점으로
적었는데, 그게 정확히 위험 지점이었다. 색인과 리더가 다른 모델로 갈려도 **1024 대 1024라
어떤 형태 검사에도 안 걸리고**, 증상은 "검색 품질이 나쁘다"로만 나타난다. 실제로 그렇게
배선돼 있던 적이 있다 — 검색은 env를 읽는데 수집은 그 설정을 무시하고 하드코딩돼 있었다.

방어는 두 겹이었다: (a) 수집과 검색이 같은 env를 읽게 하고, (b) 색인에
`mappings._meta.embedding`을 스탬프해 U2 `space_guard`가 읽기 배선 시 대조한다. (b)는 읽기
시점 방어라 **잘못된 모델로 코퍼스를 다 만든 뒤에야** 작동한다.

이후 프로바이더가 하나만 남으면서 (a)는 스위치 자체를 없애는 쪽으로 강화됐다. 다만 위험이
사라진 것은 아니다 — Cohere Embed Multilingual v3와 Embed v4가 **둘 다 1024차원**이라 모델
id만 바꿔도 같은 함정이 재현된다. `space_guard`는 그래서 계속 필요하다.

**2. 로컬에서 "깨진 것"의 상당수는 회귀가 아니라 미활성이었다.**
롤아웃 게이트가 기본 off인 유닛은 라우터 전체가 404가 된다(인증 앞단 dependency가 먼저
raise). u9 `PERSONALIZATION_ENABLED`, u8 `CITATION_GRAPH_ENABLED`가 그랬다. 404를 전환 탓으로
읽기 쉬우니 플래그부터 확인한다.

**3. citation-tree는 로컬 코퍼스가 아니라 라이브 API에 의존한다.**
Semantic Scholar `/paper/{id}/references` + Redis 캐시. 익명 rate-limit(429)이 간헐 실패 요인.

**4. 전환 중 드러난 결함 3건은 전환과 무관한 배선 버그였다.**
ingestion `OpenSearchVectorIndex`가 `use_ssl`을 전달하지 않음, backend가 `docsuri-discovery`를
`[real]` extra 없이 선언해 discovery가 조용히 스킵됨, 스타트업 마이그레이션 러너에
summarization 마이그레이션 누락. 환경을 바꾸면 이런 것이 드러난다.

**5. 준비성 점검 도구가 남았다.** `tools/local/smoke.py` — 비-에이전트 표면을 in-process
ASGI로 로컬 인프라에 태워 전수 점검(실 세션 인증, 모듈별 대표 플로우, ok/degraded/fail/skip).
전환 종료 후에도 리팩토링마다 재실행하는 회귀 방지 수단으로 계속 쓴다.
