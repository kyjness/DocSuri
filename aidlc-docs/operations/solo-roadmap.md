# 유지보수 로드맵 (2026-07)

단독 유지보수 전환(로컬 인프라 이관) 이후의 작업 계획. 두 축으로 구성한다:
(a) 기존 유닛(u1/u2/u7)의 설계 문서 대비 정합성 리뷰 및 결함 수리,
(b) 두 에이전트 모듈(novelty, 문헌탐색·근거형성)을 자율 에이전트 아키텍처로 재설계 —
최종형은 supervisor–서브 에이전트 구조. 아키텍처 결정:
[requirement-verification-questions-agent-rearchitecture.md](../inception/requirements/requirement-verification-questions-agent-rearchitecture.md) (2026-07-18 확정, Q1~Q8).

대화 메시지는 저장되지만 루프가 읽지 않고(`domain/loop.py`에 스티어링 주입 없음), 온디맨드

**⑤3을 ⑥ 뒤로 미루지 않는 이유**: `view_figure`는 설계상 DocModel/S3 **공용 부품**이므로,

## 개정 (2026-07-25) — MCP 고정 슬롯 해제 · supervisor 구성 방식

### MCP — ⑤ 2단계 고정 슬롯 해제

**MCP 도입은 독립적으로 결정된 적이 없다.** 관련 문항을 되짚으면:

- 아키텍처 Q1=C의 **선택지 설명문**에 역량 목록(`Tool Calling·Planning·Memory·MCP·멀티 에이전트`)으로
  딸려 들어온 것이 유일한 상위 근거다. 최종 구조를 고르는 문항이지 MCP 도입 문항이 아니다.
- FD 게이트 Q5는 **"MCP를 쓴다"를 전제하고 위치만** 묻는다(포트 뒤 어댑터 vs 루프 직결).
- FD 게이트 Q3은 외부 arXiv 검색을 "⑤ 2단계(MCP)로 미룬다"고만 답한다.

즉 "쓸 것인가"를 정면으로 물은 문항이 없는 채로 로드맵에 고정 단계가 생겼다. 해제한다.

해제 근거(도입을 금지하는 것이 아니라 **고정 일정에서 빼는 것**):

- 외부 도구 3종이 **이미 어댑터로 구현돼 있다** — `adapters/external/github.py`,
  `datasets.py`, arXiv 클라이언트는 u1 ingestion. MCP 교체로 늘어나는 기능은 0.
- 서드파티 MCP 서버에 **GitHub·Notion 자격증명을 위임**하게 된다. `tech-stack-decisions.md`가
  "서버는 신뢰 경계 밖"이라 적어둔 인식이 맞다면, 그 결론은 배포 환경에서 프로세스를 늘리지
  않는 쪽이다.
- 프라이버시 방어선(payload allowlist)은 어느 경우든 **우리 어댑터가 강제**하므로, MCP는
  지켜야 할 경계를 늘릴 뿐 줄이지 않는다.

**따라서**: 외부 탐색 포트의 구현을 MCP로 교체할 **필요가 실제로 생기는 시점**(도구 공급처를
자주 갈아끼우게 되거나, 자작 유지비가 교체비를 넘을 때)에 그때의 근거와 함께 도입한다.
FR-31의 "메커니즘 중립화"는 그대로 유효하다 — 포트 뒤 어댑터라는 위치(Q5=A)도 유효하다.
바뀐 것은 **일정뿐**이다.

### supervisor 구성 방식 — 별도 신설 (novelty 승격 기각)

⑦의 미결이던 "⑤ 루프의 계획층 승격 vs 별도 신설"을 **별도 신설**로 확정한다.

승격안(novelty 루프가 evidence 에이전트를 서브로 호출하며 supervisor 역할을 겸함)을 기각하는 근거:

- **역할 혼재** — novelty의 임무는 조사 + 여백 분석이다. 여기에 타 에이전트 지휘를 얹으면 하나의
  자율 루프가 프롬프트·예산·종료 조건을 두 목적에 걸쳐 갖게 된다. 종료 판정이 특히 모호해진다
  ("내 산출물 완성"과 "부하 작업 종료"가 다른 조건).
- **진입점 상실** — 문헌탐색·차별화는 각각 독립된 사용자 진입점(채팅 표면·잡)을 갖는 기능이다.
  승격안에서는 문헌탐색 단독 사용이 novelty 하위로 묻힌다. 별도 신설이면 기존 두 진입점을
  유지한 채 "주제만 던지면 알아서" 진입점이 하나 늘어난다.
- **확장 경로** — 서브가 추가될 때(요약·인용 그래프 탐색 등) 별도 신설은 서브만 붙이면 되지만,
  승격안은 novelty를 계속 부풀린다.
- **Q1=C 원문과의 정합** — "supervisor가 서브 에이전트들(문헌탐색 탐색 워커, **아이디어 생성**)을
  지휘"이므로 novelty도 서브다. 승격안은 확정된 답과 어긋난다.

용어 경계도 함께 고정한다 — **도구**는 스스로 판단하지 않는 부품(검색·요약·DocModel·figure 조회),
**서브 에이전트**는 스스로 판단하는 단위(문헌탐색·차별화). supervisor는 주로 서브 지휘와 결과
종합을 맡고, 저수준 도구는 서브가 쥔다. 구체 배선은 ⑦ 질문 게이트에서 정한다.

## ⑤a 범위 축소 (2026-07-20)

당초 계획은 u1 → u2 → u7에 같은 전면 정리를 1회씩 돌리는 것이었으나, u1 실시 후 u2·u7분은 취소한다.

u1에서 실제로 값이 나온 것은 중복 제거 자체가 아니라 **테스트가 없던 자리에서 나온 결함**이었다:
`safe_log_dict`의 API 키·연락처 평문 로깅, `migrate`/`reembed`의 alias 분기, OpenAI 어댑터의 429
재시도 불가 분류, 그리고 테스트가 0건이던 컴포넌트 3종(Postgres control-plane·circuit breaker·
redaction 헬퍼). 순수 중복 제거분은 배포가 은퇴한 현 시점에서 회수 시점이 불분명하다 —
유지보수 비용은 그 코드를 다시 만질 때 절감되는데 u1은 당분간 재작업 계획이 없다.

따라서 u2·u7에는 같은 비용을 들이지 않고, 값이 나온 관점만 옮긴다: **실입력 없이 검증되는 경로가
어디인지 점검하고, 그 자리에만 픽스처·테스트를 추가한다.** 정리는 두 유닛을 다시 만질 때
그 작업에 곁들인다.

u1 정리 패스의 부산물로 실논문 회귀 픽스처(ar5iv HTML·GROBID TEI·PDF)와 세 경로 회귀 테스트가
생겼다. 배포 은퇴로 사라진 "실제 논문이 온전히 파싱되는가"의 육안 확인을 대체하며,
파싱→청킹까지 `uv run pytest`만으로 검증된다. 갱신 절차는 `ingestion/tests/fixtures/SOURCES.md` 참조.

**⑤a(a) 테스트 공백 점검 종결 (2026-07-25).** u2·u7의 실입력/silent-degradation 경로를 감사한
결과 로드맵이 우려한 지점은 이미 커버되어 있어 **신규 u2/u7 테스트는 불필요**하다:

u7 summarization은 `refine_doc_model`(표·수식·캡션·앵커 id + PDF/GROBID `latex=None` image-only
회귀 `test_refine_doc_model_skips_image_only_formula` + U1 정규화 개행 없는 전문의 copyright 삭제
회귀 `test_single_line_full_text_survives_copyright_match`), grounding `real_corpus` 평가, 실 게이트
(`test_assets_rds_real`·`test_integration_real`의 S3 왕복)로 모두 검증된다. **이번 패스에서 실제로

테스트를 신설해 닫았다.

`_TABLE_TAG_RE`가 `^table\b`라 숫자를 요구하지 않았다. 승격 지점에서만
`caption_kind_and_number`를 쓴다(`_TABLE_TAG_RE` 자체는 유지 — 다른 호출자는 이미 float으로
확정된 대상을 판정한다). 승격 안 된 class 없는 figure가 통째로 안 보이는 것은 이 규칙이 만든
손실이 아니라 승격이 좁은 문을 냈던 **원래 상태**다.

**6. 내가 넣은 계수기가 무방비였다**. `_emit_float_placement`가 이웃과 달리 `try/except` 없이,
전체 `model_dump`를 한 번 더 하고 있었다. 관측이 산출물을 위협하면 안 된다 — 감싸고 모델을 직접
훑는다.

**7. 2단 조판에서 좌표 정렬이 읽기 순서가 아니었다**. 리뷰는 LOW로 달았지만 **좌표 경로가 float의
44.8%(636개 중 285개)를 처리하고, 50편 중 27편이 2단**이다. `(page, y)`는 오른쪽 단 위쪽 float을
왼쪽 단 아래쪽 head보다 먼저 놓는다. 키를 `(page, column, y)`로 바꿨고 — **2단으로 판정된 문서
에만** 적용한다(단단 논문에 열을 부여하면 없던 순서를 발명한다. 첫 시제품이 그 실수를 했고 단단
논문 5편이 움직여서 잡았다).

기하로 두 건 독립 검증했다:

| 논문 | float 위치 | 옛 소유자 | 새 소유자 | 판정 |
|---|---|---|---|---|
| 2502.11386 p9 | 왼쪽 단 y=347 | C. Algorithm Overview (오른쪽 단 y=186) | B. QoE Modeling (왼쪽 단 y=161) | 새 것이 옳다 |
| 2508.01047 p8 | 왼쪽 단 y=409 | Conclusion and Future Work (오른쪽 단 y=340) | Comparison with TCP Cubic (앞 페이지) | 새 것이 옳다 |

둘 다 **왼쪽 단 float이 오른쪽 단에서 시작하는 섹션에 배정**돼 있었다. 오른쪽 단은 왼쪽 단을 다
읽은 뒤에 오므로 불가능한 배정이다. 두 번째는 결과 그림이 결론 절에 들어가 있던 건이다.

**4. 겹침 조각이 캡션 폴백을 가로챈다 — 측정으로 기각.** `_best_match`가 겹침 `> 0`이면 무엇이든
돌려주므로 캡션 폴백은 겹침이 정확히 0일 때만 도달한다. 리뷰의 전제는 "붕괴한 캡션 띠는 이웃
표와 **조각만** 겹치는 경우가 흔하다"였는데, 50편의 재판독 후보 **89건을 실제로 재보니 조각이
없다**:

| | |
|---|---|
| 기하 매칭 성공 | 39 / 89 |
| 기하 매칭 전무(=캡션 폴백이 도는 경우) | **50 / 89** |
| cover(겹침/GROBID 상자) | 최소 0.114 · 중앙 0.648 · 최대 1.000 |
| cover < 0.10 | **0 / 39** |

분포가 양극단이다 — 붕괴한 캡션 띠는 겹침이 **0**이고(그래서 폴백이 실제로 다수인 50건을
결정한다), 겹치는 것들은 충분히 겹친다. 기하와 캡션이 서로 다른 표를 고른 것은 3건뿐인데 전부
cover 0.63~0.79로 기하 쪽이 더 나은 증인이다. **최소 겹침 문턱은 데이터가 지지하는 어떤 값에서도
89건 중 0건의 판정을 바꾸고**, 더 올리면 회수율만 깎는다. 코드 변경 없이 근거를 주석에 남겨
종결한다.

**측정**: float 위치 전수 대조에서 **22개 라벨 그룹(약 30개 float)이 17편에서 이동**, float 총계는
616 불변.

- **PDF 보존 스윕**(50편·22신호): 바뀐 값이 **1개뿐**이고 그것도 개선이다 —
  `2306.05494v5 empty_sections 4 → 3`, 빈 껍데기였던 절이 제 float을 받았다. 결함 집계
  (empty_table 21 / table_lost 19 / figure_lost 12 / coverage_low 1)는 전부 동일.
- **ar5iv 보존 스윕**(50편·18신호): **2504.11054 한 편만** 바뀌었다 — 2번 수리가 겨냥한 바로 그
  논문에서 문단 2개가 표 1개(4행)가 되고 캡션이 하나 늘었다. 회수된 셀은 전부 `fullText`에 남아
  있다(`body_chars` -29는 셀 구분자 렌더링 차이지 손실이 아니다).
- fixture digest 3종 무변경.

**수리 중 내가 만든 결함 1건도 잡았다**: `layout`을 `if body is not None` 안에서만 묶어놓고
바깥의 말미 섹션 호출에서 읽어, **`<body>` 없는 TEI가 `UnboundLocalError`로 죽었다**. 원래는
조용히 빈 doc-model로 degrade하던 경로다(빌더가 그걸 받아 flat-text로 폴백한다). 분기 앞에서
바인딩하고 테스트로 못 박았다 — 실논문 50편은 전부 body가 있어 스윕으로는 잡히지 않는다.

### ⑧-1.5 — 파싱 소스 사다리 개편 (2026-08-10 확정) — ✅ 종결 (PR #20 머지)

⑧-2 착수 전에 사다리 자체를 재확정했다(BR-29/BR-30 개정 참조). 브랜치
`feature/u1-parse-source-ladder`, 확정 사다리:

```
arXiv:  ar5iv HTML(품질검사) → arXiv PDF → GROBID(품질검사) → 코퍼스 제외
S2/OA:  PDF → GROBID → 코퍼스 제외          (기존 경로 — 배선만 준비, 기동은 별도)
전문:   ar5iv HTML → PDF 텍스트
제거:   native HTML 전부(doc-model·전문 양쪽), PDF 평문 doc-model
```

결정 근거(실측은 메모리 `parse-source-ladder`와 BR 개정에 기록):

- **native 제거** — 운영 검수에서 화면 품질 불량 반복 확인. 좋은 표본도 있으나(2512.08879의
  표·알고리즘은 GROBID보다 정확했다) 소스 신뢰가 논문마다 갈리는 것 자체가 비용이라 제거로 확정.
- **품질검사를 ar5iv에도** — 깨짐은 LaTeXML 공통(동일 10편에서 ar5iv 3편·native 4편 `ltx_ERROR`).
  기존 가드(본문 500자)는 8,905자짜리 깨진 변환(2502.10208)을 통과시킨다.
- **평문 doc-model 제거** — 섹션 2·문단 2 글자 뭉치를 서빙하지 않는다. GROBID 단이 대신한다.
- **실패=코퍼스 제외** — 색인하지 않고 저장한 전문도 삭제. 본문 없는 검색 결과를 없앤다.
- **S2/OA 폴백 무용** — OpenAlex `locations`가 arXiv 프리프린트에 arXiv PDF만 반환(실측).
  "진 소스 PDF 주소 보존" 안은 폐기. S2/OA는 수집(비-arXiv 발견) 전용.

이후 별도 브랜치로 크롭 프레이밍(캡션·본문 잘라내기 + Algorithm 통째 크롭 — 승인됨)을 처리하고,
**⑧-2 배치는 두 브랜치 머지 후 1회만** 돌린다. 저장소의 native_html 산출물 10,638편은 배치가
자연히 덮어쓴다(서빙은 이미 `_REJECTED_SOURCE_TIERS` 게이트가 막고 있다).

### ⑧-1.6 — 크롭 프레이밍 (2026-08-10) — 진행 중

⑧-1.5로 arXiv 논문의 상당수가 GROBID 단으로 내려오는데, 그 단의 그림·표·알고리즘은 전부
**PDF 페이지 크롭 이미지**로만 화면에 나온다. 그 크롭 영역이 네 가지로 망가져 있었다.
브랜치 `feature/u1-crop-framing`, 규칙은 BR-23a.

**결함과 측정** (리포 TEI 픽스처 3편 + 무작위 50편 스윕, 크롭 스펙 2,111개):

1. **크롭의 10~69%가 캡션 텍스트.** float `coords`는 캡션 줄 나열 + 내용 영역인데 통째로
   union하고 있었다. 뷰어는 `<figcaption>`으로 캡션을 이미 렌더한다.
2. **float의 29%가 캡션 띠만 저장.** `<graphic>`/`<table>` 좌표가 없는 float은 크롭이 캡션 줄
   높이 그대로다 — 독자는 그림 자리에서 캡션 문장 사진을 본다.
3. **표 크롭이 다른 페이지를 가리킴.** 2607.16138: float은 p11(캡션 띠), `<table>`은 p12.
4. **알고리즘은 첫 조각만 크롭.** `_append_to_listing`이 텍스트만 합치고 좌표를 버렸다.
   2607.16138: 297자짜리 리스팅의 크롭이 223x21pt — 첫 한 줄만 찍힌 이미지.

**수리 판정** (50편 스윕, before/after 동일 TEI·PDF 캐시):

| | |
|---|---|
| 크롭 스펙 총수 | 2,111 (양쪽 동일 — 블록 생성은 건드리지 않았다) |
| 영역이 바뀐 것 | 427 (그림 247 · 표 179 · 수식 1) |
| 저장하지 않게 된 캡션 띠 | 145 (그림 124 · 표 21) |
| 면적비 중앙값 | 0.73 |

렌더 대조를 눈으로 봤다(그림·표 6쌍). 캡션 문단과 본문 산문이 빠지고 도판·격자는 온전하다 —
2409.08036 표는 "표 + 본문 한 페이지"에서 격자만으로, 2404.03784 표는 2단 페이지 전체에서
해당 표만으로 좁혀졌다.

**표에서 실제 손실을 한 번 만들었다가 잡았다.** 표 float은 이 표본에서 **181건 전부 단일 영역**
이라 항상 "`<table>` 상자를 믿는" 가지를 타는데, 그 상자가 자주 괘선 띠로 붕괴한다. 2505.05549는
31행짜리 표의 크롭이 헤더 두 단어 조각이 됐다. 수리: `AssetCropSpec`에 float 상자를 실어
보내고, 렌더 시 pdfplumber로 **행을 따라 되키운다**(기존 `_table_row_span` 재사용). x는 박스가
앉은 행을 따라 달리되 **단 사이 홈에서 끊는다** — 실측으로 2404.03784 p6의 홈은 152pt인데 그
옆 표 내부 최대 간격은 52pt, 붕괴 사례의 표 내부 최대 간격은 34pt라 1인치가 두 무리 사이에 있다.

판정 지표는 **GROBID 자신이 읽은 행 수**로 잡았다. "옛 크롭보다 열 구조 행이 줄었나"는 옛 크롭이
이웃 표까지 삼켰던 경우를 손실로 오보한다.

| | before | after |
|---|---|---|
| GROBID 행 수보다 적게 담긴 표 크롭 | 65 / 177 | **63 / 177** |

즉 표 내용은 기준선 대비 손실이 없고, 캡션과 이웃 본문만 빠졌다.

**캡션 띠 판정은 높이 문턱이 아니라 텍스트로 한다.** pdfium으로 bbox 안의 텍스트를 읽어 캡션과
길이를 비교한다(영문자·숫자만 남긴 정규형). 픽스처 2편 분포: 캡션 띠 1.00~1.24, 실제 콘텐츠
2.96~6.32 — 상한 2.0은 그 빈 구간에 둔다. 하한 0.5도 같은 무게다: 벡터 패스로만 그린 그림은
텍스트가 아예 없는데 "텍스트 없음"은 캡션 띠라는 증거가 아니다.

**⑧-2에 딸리는 비용**: 표 크롭이 있는 논문에 pdfplumber `extract_words` 패스가 붙는다
(50편·표 크롭 190건에 20초 — Docling 항에 비하면 작다). 표 크롭이 없으면 열리지 않는다.

### ⑧-1.7 — S2/OpenAlex 경로 기동 검증 (2026-08-10) — 진행 중

u1을 닫으려면 arXiv 경로만이 아니라 이 경로도 실제로 돌려보고 고쳐야 한다. 이 경로는 배선만 돼
있었고 **한 번도 실행된 적이 없었다** — `PostgresControlPlaneStore`가 게이트 뒤에서 아무도 안
돌던 것과 같은 자리다. 돌려봤더니 **6편 중 0편**이 doc-model까지 가지 못했다. 어댑터는 멀쩡했고
(OpenAlex 25건·S2 306건 수확 성공) 실패는 전부 출판사와 대화하는 방식에 있었다. 규칙은 BR-23b.

| 결함 | 실측 |
|---|---|
| UA 없이 요청 | Springer·Nature가 **200 + HTML 3KB**, Cureus가 403. UA를 붙이면 각각 1.98MB·1.43MB PDF, 200 |
| 본문이 PDF인지 미검사 | 3KB HTML → GROBID 500 → **retriable → DLQ 무한 적재** |
| OpenAlex 분야 필터 부재 | 한 주 수확 상위가 중환자의학·알츠하이머 진단·수자원 관리 |
| 질의가 AND | S2 306건 → **22,039건**(OR, 2025년), OpenAlex 539건 → 9,305건(1주) |

**수리 후 도달률** (동일 창, GROBID 로컬):

| 소스 | 전 | 후 | 남은 실패 |
|---|---|---|---|
| OpenAlex | 0/6 | **9/20** | 403 10 · 타임아웃 1 |
| Semantic Scholar | — | **7/10** | 403 2 · 404 1 |

도달한 doc-model 품질은 arXiv 경로와 같다(예: 31섹션·114,005자·그림 18·표 8).

**남는 한계 셋 — 코드로 못 푼다**:

- **403이 OpenAlex 슬라이스의 약 50%.** MDPI·ACS·Wiley·ACM의 봇 차단이고 UA로 안 풀린다.
  대체 사본 순회를 넣었지만 **이 표본에선 거의 못 살렸다** — OpenAlex 50건 중 호스트가 실제로
  다른 사본을 가진 레코드가 **2건뿐**이다(`locations[]`는 대개 primary를 한 번 더 싣는다).
  폴백은 비용이 없고 사본이 있을 때 작동하므로 유지하되, 403 손실은 그대로다.
- **두 소스의 "Computer Science"가 느슨하다.** 분야 필터를 켜도 수의병리학·치의학 교육이
  CS로 분류돼 들어온다. 슬라이스는 "OpenAlex/S2가 CS라 부르는 것"이지 arXiv cs 슬라이스가 아니다.
- **S2는 OR로 바꾸면 저널 품질이 크게 낮아진다.** 실행 표본에 소규모·약탈적 저널이 다수였다.
  실제로 켤 때 venue 필터가 필요한지는 ⑧-2 이후 판단한다.

**후속으로 기록**: arXiv 어댑터도 UA를 안 보낸다. 지금 차단되고 있지 않아 배치 직전에 그 경로의
요청 모양을 바꾸지 않았다. ⑧-2 이후 정리 대상.

### ⑧-1.8 — 표 재판독이 못 고치는 것 (2026-08-10) — 진행 중

⑧-1.6의 크롭 스윕에서 딸려 나온 수치를 정면으로 봤다: 50편에 표 212개 중 **61개(29%)가 셀이
붙은 채로 서빙된다**. GROBID가 여러 열을 한 셀에 뭉친 상태로, 텍스트는 다 있어 검색·인용은 되지만
화면에서 표가 표로 보이지 않는다. Docling 재판독이 이걸 고치라고 있는 장치인데 후보 115건 중
54건만 성공했다. **왜 실패하는지 먼저 분류했다** (미수리 상위 10편, 후보 54건을 실제 재현):

| 판정 | 건수 | 성격 |
|---|---|---|
| 검증 게이트에서 거부 | 24 (44%) | Docling은 제대로 읽었는데 반려 |
| 매칭 실패 | 16 (30%) | 그 영역에 Docling 표가 없음(12건은 그 페이지에서 표 0개) |
| 수리 성공 | 14 (26%) | |

거부 24건을 토큰 수준까지 뜯으니 **재구성이 틀린 게 아니라 페이지 쪽을 잘못 읽고 있었다**:

- **회전된 라벨(10건)** — pdfplumber가 위→아래 라벨을 역순으로 돌려준다(`elbmesnE`·`DSN`·`EN`·
  `TN`). 891개 토큰 중 **4개** 때문에 제대로 재구성된 50행 표가 통째로 반려됐다.
- **음수 부호(1건)** — 논문은 U+2212, 셀은 ASCII `-`.
- **적게 읽음(6건)** — **의도된 가드**. 뭉쳐졌지만 완전한 데이터를 깔끔하지만 부분적인 것과
  바꾸지 않는다. 손대지 않는다.

또 **조용한 절단**을 찾았다: `_max_pages=12`가 의심 페이지를 자르는데 잘린 페이지의 후보는
재판독 시도조차 없이 "매칭 실패"로 집계된다. 50편 중 1편이 14개 페이지에 후보를 퍼뜨려 5건
(전체 후보의 4%)을 잃었다. 로그로 드러내고 `DOCSURI_DOCLING_MAX_PAGES`로 조절 가능하게 했다.

**그리고 상한을 올릴 값이 있는지 실제로 쟀다** — 걸린 그 논문(2409.08036, 후보 19건)을 두 상한으로
돌렸다:

| 상한 | 수리 | Docling 시간 |
|---|---|---|
| 12 (기본) | 8 | 195초 |
| 24 | **9** | 200초 |

**후보 5건을 되찾아도 수리는 1건만 는다.** 나머지는 매칭·검증에서 어차피 떨어진다. 비용은
작지만(+5초) 이득도 작으므로 **기본 12를 유지**한다 — ⑧-2가 이 수치를 근거로 다시 판단하면 된다.
이 항목은 로드맵 ⑧-2의 "빈 표 경로에 별도 페이지 상한을 둘지" 미결 항목에 대한 답이기도 하다.

**판정** (같은 50편 캐시):

| | 전 | 후 |
|---|---|---|
| 셀이 붙은 채 남는 표 | 61 (29%) | **56 (26%)** |
| 수리 성공 | 54 | 59 |
| 빈 표 | 7 | 7 |

**남는 26%의 성격** — 대부분 Docling이 그 영역에서 표를 아예 찾지 못하는 경우와 위의 "적게 읽음"
가드다. 전자는 모델 한계라 코드로 못 푼다. 표는 rows가 정본이고 붙은 셀도 텍스트는 남아
검색·인용은 되며, 페이지 크롭 이미지가 시각적 백업으로 함께 붙는다.

### ⑧-2 — 재파싱 + 재색인

- **arXiv 경로 사다리는 ⑧-1.5에서 재확정** — `ar5iv HTML(품질검사) → arXiv PDF → GROBID`.
  native HTML 단은 제거됐다. 재파싱 시간 산정에는 품질검사 탈락·ar5iv 부재분이 GROBID로
  내려가는 비중(최신 논문일수록 큼)을 반영해야 한다.
- **임베딩 비용은 제약이 아니다** — `text-embedding-3-small`(1024차원) 기준 편당 약 $0.00025,
  30,065편에 **약 $6**.
- **제약은 색인 메모리다** — 현재 논문당 약 101청크이므로 30,065편이면 약 3.0M 벡터,
  k-NN 그래프에 약 12GB가 필요한데 RAM은 7.5GB다. 착수 전에 완화책을 정한다:
  청크 크기 상향(현 `max_chunk_chars=2400`) / 출력 차원 축소(512) / 양자화·on-disk /
  WSL 메모리 상향. 청크 반감 + 차원 512면 약 3GB로 떨어진다.
- **저장된 앵커를 무효화해야 한다** — 재파싱은 블록 id를 다시 매기므로, 이미 저장된 u7 요약과
  evidence 앵커(FR-12 label→blockId 이월분)가 **존재하지만 다른 문단을 가리키는** 상태가 된다.
  존재 검사로는 절대 안 잡히는 오귀속이라 "링크가 깨졌다"보다 나쁘다 — 사용자에게는 근거가
  멀쩡히 붙어 있는 것으로 보인다. 배치에 무효화(또는 재생성) 단계를 넣고, 재파싱된 논문의
  캐시된 요약·앵커를 함께 버린다. `⑧-1 3차`의 id 구멍 수리로 이동 폭이 줄었을 뿐 원인은 남는다.
- **자산이 딸려온다** — @8~@10 수정이 float 인식과 캡션 결합을 바꿨으므로 crop 대상·개수가
  달라진다. doc-model만이 아니라 자산 재추출 + `paper_asset` 재등록 범위를 함께 정한다.
- **Docling 재판독이 배치 시간의 지배 항이다** — `⑧-1 3차`에서 빈 표도 재판독 대상에 넣으면서
  이 경로가 논문의 **25% → 52%**로 늘었다. 실측 페이지당 1.3~11.1초에 `_max_pages=12`라
  한 편이 최악 ~60초를 쓴다. 3만편 중 약 1.5만편이 이 경로를 타면 **CPU 수십 시간**이고,
  이 유닛의 다른 모든 비용을 합친 것보다 크다. 코드 품질 문제가 아니라 예산 문제라
  `/simplify`에서 손대지 않았다. 착수 전에 정한다: 빈 표 경로에 별도(더 낮은) 페이지 상한을
  둘지, 아니면 전체 예산을 받아들일지. 회수되지 않는 재판독은 순수 손실이다.
- **2026년치가 비어 있다**(193편). 확대 여부는 재파싱 품질 확인 후 별도 판단.
- **손실 예산 게이트는 reparse에 내장됐다**(2026-08-10 리뷰 수리) — 제외+오류 비율이
  `DOCSURI_REPARSE_MAX_FAILURE_RATIO`(기본 5%)를 넘으면 비-0 종료로 finalize→cutover를 막는다.
  단 **`DOCSURI_REEMBED_MIN_DOCUMENTS`의 기본은 여전히 1**이다 — 배치 런북에서 기대 문서 수
  근사치(≈3만)로 명시 설정할 것. reparse의 종료 코드를 무시하고 finalize를 손으로 돌리면
  바닥 1이 그대로 통과한다.
- **제외 논문의 기존 색인 항목 처리** — 재파싱에서 빌드가 실패해 제외된(state=EXCLUDED) 논문의
  구버전 청크는 색인에 남는다(구버전 콘텐츠는 유효하므로 의도된 기본값). 배치에서 지울지 남길지
  별도 결정.

## ⑨ 에이전트 잔여 수정 (2026-08-06 확정)

⑤·⑥ 완주 후 남은 **의도 대비 동작 불일치** 2건. 기능 추가가 아니라 정합 수리다.

### ⑨-1 novelty 종료 판단 — 바닥과 천장을 분리한다

현재 `domain/loop.py`는 `REQUIRED_ARTIFACT_KINDS`(evidence·similar_works·gap_analysis) 3종이
채워지면 **모델 의사와 무관하게 그 자리에서** `COMPLETED`로 끊고, 안 채워졌으면 종료 제안을
거부한다. 즉 **바닥과 천장이 같은 지점**이라 모델이 판단할 구간이 없다.

evidence 쪽은 이미 의도한 형태다 — 바닥은 "근거 0건이면 종료 불가"(INV-EV-2), 천장은 예산,
그 사이는 모델이 정한다. novelty를 같은 형태로 맞춘다: **3종은 바닥으로만 쓰고**, 채워진 뒤에도
더 조사할지는 모델의 종료 제안을 수용하는 방식으로 두며, 천장은 예산이 잡는다.

대가로 잡 소요·비용이 지금보다 늘어난다(예산 상한 안에서). 잡 결과물의 형태는 3종 바닥이
보장하므로 프론트·후속 소비 계약은 그대로다.

### ⑨-2 evidence 중간 취소

evidence에는 스티어링도 취소도 없다(novelty에만 있다). **취소만 넣는다.**

턴이 짧아(수초~30초) 방향 전환은 다음 턴에 말하면 되므로 스티어링의 값이 작은 반면,
메시지 저장·주입 시점·경합 처리가 전부 딸려온다. 반면 취소는 길이와 무관하게 필요하다 —
탐색이 길어질 때 사용자가 비용을 멈출 수단이 있어야 한다. novelty의 협조적 취소(BR-RA8:
진행 중 도구 호출 완료 후 턴 경계에서 탈출)와 같은 방식으로 맞춘다.
